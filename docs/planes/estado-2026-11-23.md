### Supabase: local ahora, cloud después

Hoy el backend corre local y la PWA es offline-first. El despliegue a **Supabase Cloud** se hace
cuando **#62** (enrolamiento) y **#65** (materializador) estén cerrados, con URL y publishable key por
entorno, admin creado por seed o `enroll()`, y sin `service_role` en el cliente. Decisión completa en
**DEC-20261123-1349-9c5d5a**.

Cómo se hará, en orden:

1. `pnpm db:test` verde en local y el write path probado con dos dispositivos.
2. `supabase link --project-ref <ref>` + `supabase db push` (migraciones forward-only); seed **solo**
   con datos ficticios.
3. Admin: script/seed idempotente que crea `members` + `devices` + `olla_members` con rol `admin`, o
   `enroll()` si ya existe; contraseña de un solo uso y cambio al primer ingreso.
4. `VITE_SUPABASE_URL` y `VITE_SUPABASE_PUBLISHABLE_KEY` en el hosting; nada hardcodeado y nada de
   `service_role`.
5. Smoke contra cloud: anónimo → 0 filas; admin → sus ollas; enrolado → 1 olla; escritura solo de su
   rol. Si falla, no se publica la URL.
