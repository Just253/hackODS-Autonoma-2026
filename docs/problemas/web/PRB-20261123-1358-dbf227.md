## Qué se observa

La app abre con **todas las rutas para cualquiera**: no hay sesión, rol ni olla activa. La cocinera, la
organizadora, el nutricionista y el admin ven el mismo cascarón y las mismas pantallas; no hay un
divisor de contexto que diga “Olla San Juan · Cocinera”.

## Cómo se reproduce

Abrir el preview y recorrer `/padron`, `/servicio`, `/comprobante`, `/presupuesto`, `/precios`,
`/solicitud`, `/reporte`: las siete están siempre en la barra/rail. `rg -n "rol|sesion|member|ollaActiva" apps/web/src`
no devuelve una sesión de UI; `Shell.tsx` solo conoce la olla demo.

## Impacto

No se pueden mostrar las perspectivas que el producto promete —cocinera sin salud/dinero,
organizadora con padrón/comprobantes, nutricionista con menú/firma, admin con ollas/miembros—. Todo
queda en una demo única y el jurado no ve la separación de roles.

## Qué se esperaba

Una sesión mínima (`{memberId, ollaId, rol}`), un divisor de contexto visible y navegación/guardas por
rol; en demo, un selector; en cloud, el JWT y `olla_members`.

## Evidencia

- `apps/web/src/app/Shell.tsx` y `navegacion.ts`: mismas rutas para todos.
- `apps/web/src/app/router.tsx`: sin guardas.
- DEC de roles `DEC-20261123-1349-d04467` y issue **#62**.

## Opciones y decisión

| Opción | Costo | Riesgo | Veredicto |
|---|---|---|---|
| Ocultar con CSS | bajo | la API se llama igual | no |
| Selector de rol en demo + guardas | medio | no es auth real | **sí, para demo** |
| JWT real desde el inicio | alto | bloquea la demo hasta #62 | después |

## Cómo se cierra

Test de navegación por rol: cocinera no ve “Comprobante” ni “Presupuesto”; nutricionista ve “Menú” y
“Salud”; admin ve “Ollas” y “Miembros”. La API devuelve 42501 si se llama igual. Ver el DEC de
perspectivas.
